# Orvio

**源码公开，仅限非商业用途。**

Orvio 把已学习的实体按键、电脑快捷键和中文语音指令接到同一组音乐与双主机操作。macOS 版常驻菜单栏，Windows 版常驻系统托盘。两端各自学习设备和校准显示器，因为同一遥控器在不同系统、连接模式和 KMFU 端口下可以报告不同的输入。

这是开发中的源码版本。安装包需自行构建；旧版本安装包不随源码仓库上传。构建结果位于 `build/`。macOS 升级时先从菜单栏退出旧版，再解压 `Orvio-0.3.0-macos.zip` 并打开其中的 `Orvio.app`。Windows 11 x64 请完整解压 `Orvio-0.3.0-windows-x64.zip`，运行其中的 `Orvio.exe`。Windows 包已包含 .NET 运行时。

首次打开 0.3.0 会显示设置引导。Mac 按输入监控、辅助功能、麦克风、语音识别和录屏的顺序检查状态。点当前步骤的按钮前往系统设置或打开系统授权弹窗。授权后回到应用检查，系统要求重开时按提示操作。Windows 引导依次检查遥控器连接、桌面应用的麦克风访问和本地 Whisper 模型配置。可以暂时跳过，从 Mac 控制台左下角的「权限引导」或 Windows 顶部的「设置引导」重新进入。

macOS 的「打开输入监控设置」按钮会跳转到「系统设置 → 隐私与安全 → 输入监控」。打开当前 Orvio 的开关后，回到应用确认「输入监控可用」。按键诊断会显示按下到松开的时长，状态栏会显示录音、识别和取消原因。从按键页切到语音页时，已启用的语音键可以继续完成当前录音。

## 使用

功能组合分为「原生」「媒体」「主机切换」。启用「功能组合切换快捷键」后，Mac 用 ⌃⌥⇧F10 循环切换，用 ⌃⌥⇧1、2、3 直接选择三组。Windows 对应 Ctrl+Alt+Shift+F10 和 Ctrl+Alt+Shift+1、2、3。也可以在按键页学习独立的「模式键」。模式键在各组合中都保留，长按不循环。

Mac 在设备层隔离当前组合中已启用的 T1 和 RC003 键盘键、媒体键，映射动作在确认隔离后执行。切回原生、停用绑定和退出应用时会还原对应设置，按住键时更换组合会等到松开再应用。首次使用组合时，沿用已学习的菜单键作为主机组合的切换键，已有主机绑定继续使用。OK 请先关闭空鼠，以回车方式学习。鼠标左键形式的 OK、合并键鼠集合及未能确认隔离的绑定会显示暂停状态。Windows 的组合快捷键已接入，遥控器设备级隔离仍需接通兼容的已签名过滤驱动，新组合中的实体按键映射当前暂停。

两端的「设备导览」可以切换 T1 和小米蓝牙遥控器 2 Pro（RC003）。Mac 提供可拖动的 3D 模型、按键标注和当前映射状态，Windows 提供带可点击按键的渲染示意。从导览可以直接进入对应设备的按键配置。小米设备的特殊键值能否映射，以当前系统的按键诊断收到事件为准。侧栏和设备卡片参考了 [无线麦项目](https://github.com/HD838A/remote-mic-app) 的界面。

1. **按键**。macOS 上直连 T1 接收器时，按键页会自动选择它的键盘和媒体／鼠标集合。点「左方向 · 上一曲」或「右方向 · 下一曲」旁的学习，再按下并松开目标键。要更换播放／暂停，点「换成 OK／学习」，关闭飞鼠的空鼠模式后按 OK；这时用回车报告学习，原主页绑定会被替换。空鼠开启时的 OK 仍会产生原生左键点击，学成后要手动启用。蓝牙和 KMFU 可在诊断中选独立集合；合并的鼠标输入不能单独区分是飞鼠还是普通鼠标。直连标准方向键和回车自动启用，其余新绑定需确认原生动作后才启用。开启「媒体模式」后，方向键绑定才会切歌。
2. **音乐**。播放器列表统一决定界面按钮、遥控器和电脑快捷键的控制目标。macOS 对网易云调用应用自己的控件，对汽水使用已验证的应用内快捷键，指令发送到所选应用的进程。切换播放器会使旧目标的待执行操作失效。Windows 优先匹配所选播放器的媒体会话，也可配置应用内快捷键。定向控制不可用时显示对应错误。数字音频输出是否支持系统音量由设备决定。
3. **主机**。在显示器 OSD 开启 DDC/CI，核对显示器及 Windows、Mac 的两个实际输入值。macOS 需要启动 BetterDisplay。先测试两端「仅切画面」，再在官方 KMFU 中配置切换热键及端口跟随，逐项检查键盘、鼠标、音响和飞鼠接收器。确认外设当前归属后再试联合切换。只要厂商热键仍是翻转操作，应用只在知道起点时发送一次。画面或外设无法读回时，界面会显示待确认，可在 KMFU 或 OSD 单独恢复。
4. **语音**。选中已验证有输入电平的 T1 音频端点。飞鼠语音键可见但飞鼠麦克风不可读时，可选择主机麦克风。macOS 支持设备端中文识别，也可配置 `whisper-cli` 与多语种模型。Windows 使用 `whisper-cli.exe` 与多语种模型。常规按住说话在松开后识别，T1 短脉冲语音键由说完后的静音触发识别。录音在 15 秒时自动取消。也可在语音页输入文字测试，例如「播放今日推荐」「音量调到 35%」「切到 Mac」。

macOS 上连接小米蓝牙遥控器 2 Pro（RC003，`2717:32B8`）后，进入「按键映射 → 小米蓝牙遥控器」，学习并启用需要的按键。小米和 T1 各自保存绑定，可以同时使用。「启用映射」和「媒体模式」对两只遥控器生效。小米语音键可绑定按住说话，实际录音来自「语音」页所选的系统音频输入。

两端的长按菜单键和「切到另一台」都支持仅切画面。「长按菜单键时同时交接 KMFU 外设」关闭时，依据实时 DDC 输入切到另一台，外设交接另行触发。同一个显示器如果只允许当前信号源发送 DDC，切到 Windows 后须由 Windows 版发起返回。Windows 端要保存自己的显示器和两个输入值，并接收到长按菜单键或已设定的切换快捷键。始终连接 Mac 的蓝牙遥控器不会把菜单键交给 Windows。

主机页可用接收器和默认音响判断本机外设归属。只有同一个独立 HID 集合和同一默认音响同时出现才推断本机接管。请先用 KMFU 验证两者在切走时消失、切回来时重现，且键鼠随端口移动。合并的 KMFU HID 集合不用于自动判断。若缺少可靠的端口归属信号，可在主机页手动确认。

macOS 的每日推荐使用网易云音乐客户端的登录态。点歌支持网易云音乐和汽水音乐，可在「音乐控制」选择播放器，也可说「用汽水音乐播放某位歌手的歌名」。控制台读取播放器窗口来定位搜索和播放控件，指定歌手时同时核对歌名和歌手。可在「音乐」页查看本机模型状态。支持 Apple Intelligence 本机模型及中文的系统可以用该模型辅助判断意图和界面候选，其他系统使用规则匹配。无法确认播放时，控制台会提示停在哪一步。

macOS 在「语音」页提供可选的小爱音箱接入。直接说「打开网易云音乐，播放今日推荐」走本机操作。启用小爱入口后，以「小爱同学」开头的每日推荐指令会尝试小爱音箱和巴法回传。桥接无法完成时按原指令转回本机执行。两端也可用「只切画面到 Windows」或「画面切到 Mac mini」单独切换显示输入。[查看 L05C 音箱与巴法接入步骤](tools/README.md)。

## 构建

在工作区根目录运行。macOS 需要 Xcode 及 Swift 6，目标为 macOS 14 及以上。Windows 需要 .NET 10 SDK，建议在 Windows 11 x64 测试桌面与硬件。

```sh
swift test --package-path macos
xcodebuild -project macos/T1Controller.xcodeproj -scheme T1Controller -configuration Release -derivedDataPath build/macos build
open build/macos/Build/Products/Release/Orvio.app
```

完整的小爱桥接组件由通用包脚本打入应用。先在本机准备 `paho-mqtt==2.1.0`，再运行：

```sh
python3 -m pip install --target /private/tmp/t1-bemfa-paho paho-mqtt==2.1.0
bash tools/package_macos.sh /private/tmp/t1-bemfa-paho
```

```powershell
dotnet test windows/T1Controller.sln -c Release
dotnet publish windows/T1Controller/T1Controller.csproj -c Release -r win-x64 --self-contained true -o build/windows
.\build\windows\Orvio.exe
```

两端配置分别位于 `~/Library/Application Support/T1Controller/settings.json` 和 `%LOCALAPPDATA%\T1Controller\settings.json`。用界面保存本机配置。设备学习和输入源校准产生的值跟随实际硬件。共享动作约定与中文样例位于 `shared/contract.json`、`shared/intent-fixtures.json`。

macOS 通用版包含 arm64 和 x86_64。macOS 26 及以上使用原生 Liquid Glass，较早受支持的版本使用系统毛玻璃材质。汽水音乐的播放器音量使用应用内默认快捷键 ⌘↑／⌘↓，需要辅助功能权限。Windows x64 自包含包可在 Mac 上交叉构建，桌面启动和硬件联动需在 Windows 真机验证。

## 实机验收记录

这台 Mac 上，T1 的菜单键经 KMFU 键盘集合上报 `hid:0007:0065:00` 的按下与松开。直连接收器 `1915:1025` 后，主页键、静音键和语音键在「媒体／鼠标」集合分别上报 `hid:000C:0223:02`、`hid:000C:00E2:02` 和 `hid:000C:00CF:02` 的按下与松开。学习菜单键时选择「键盘」，学习主页、静音和语音键时选择「媒体／鼠标」。若换设备集合，先重新选择要学习的键位。

直连接收器出现了自带的 `Mic Device`，为 USB 单声道、16 kHz。macOS 声效设置的输入电平在试说期间出现活动。经 KMFU 测试时，系统录音设备列表只有虚拟麦克风。

本机试说时，T1 语音键的按下与松开报告相隔约 118–134 毫秒。macOS 版会用这类短脉冲启动与接收器同一 USB 位置的 `Mic Device`。短脉冲模式结合设备端语音分类、静音和音频中断判断句尾。持续噪声阻止判断时，约 7 秒会关闭麦克风并转写已收录的音频。也可以再次按一下语音键，或点语音页的「停止并转写」。约 5 秒内没有检测到音频活动则结束本轮。支持真实松开事件的按键仍按松手停止，最长录音 15 秒。

macOS 0.1.5 按所选麦克风的设备 ID 建立纯输入会话，并按收到的 PCM 格式处理音频。若没有检测到语音，状态栏会区分未收到音频、音频没有电平和输入电平低于语音检测门限。

本机用飞鼠语音键实测，0.1.5 从 `Mic Device` 收到约 6 秒的 16 kHz 单声道 PCM，自动停止录音并在语音页完整显示「窗外有三只蓝色的小鸟」。

| 测试 | 记录内容 |
| --- | --- |
| Windows / macOS × 2.4G 直连、2.4G 经 KMFU、蓝牙 | 设备名、HID 集合、按下/松开、重复、原生动作、语音 PCM、电平与断连恢复 |
| Windows → Mac、Mac → Windows 各 10 次 | 每次记录画面、键盘、鼠标、音响、接收器是否到目标主机，记录失败与恢复路径 |
| 两个音乐应用同时运行 | 选择目标后核对实际播放、暂停、上一曲、下一曲和音量 |
