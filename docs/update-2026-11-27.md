## 遥控器与模式

- 新增 Chromecast Voice Remote 的独立设备配置、媒体预设、基础按键自定义及学习入口。
- 针对本机 `18D1:9450 / 0x011B` 的异常两字节消费键报告提供可选日志兼容入口；适用范围、归属限制及需用户授权的系统日志配置见 [Chromecast 说明](chromecast-remote.md)。该配置不会随应用自动安装。
- 电源与信号源的蓝牙键值分别为 `0x019E`、`0x0189`，加入学习与解码路径；默认不执行电源或信号切换动作。
- 原生模式释放应用拥有的所有按键隔离。Mac 的 T1／小米保留系统按键及系统听写，Google 通过兼容层提供原生输入；Windows 保留三款的 Windows 原生行为。
- Mac、Windows 共用三款遥控器的三维网格、按键锚点及标注。Chromecast 背部使用连续椭圆弧线。切换模式时显示不抢占输入焦点的桌面提示。

## 静音修复

原媒体静音依赖名为“静音”的辅助功能控件，播放器不提供该控件时操作失败。本机数字输出也未提供可写的 HAL 静音接口，旧 tap 配置本身不足以证明声音已经切断。

Mac 的兼容静音使用私有 CoreAudio tap、以实际输出设备为时钟源的私有聚合设备和运行中的 IO 回调。音频注册及启动在后台执行，实际回调运行后才确认处理链路可用。静音回调不读取、记录或发送输入音频样本，只清零聚合设备自身的输出贡献。取消静音、正常退出及系统静音涉及的输出切换会解除对应资源。

原生静音使用系统范围。媒体模式根据“优先调整播放器音量”选择所选播放器或系统输出；播放器范围只包含对应应用包内的音频进程及 helper。三款遥控器、界面按钮和电脑快捷键使用同一分发路径。兼容静音需要 macOS 14.2+，首次使用会单独请求系统音频许可；本地重新签名可能使原有授权失配。

Windows 使用所选播放器的主进程和音频子进程查找 WASAPI 会话，将多个会话统一切换到同一静音状态并读回。设置过程中保留播放器选择变更检查。

## 原生语音转文字修复

Google 使用独立 ATVV 蓝牙语音服务：核验 PnP 身份、协商采样格式、解码 ADPCM、按住收音、松开停流，再进行本地识别。断连、异常停流、音频间断和 15 秒限制会关闭或取消录音。

原生模式将转写送到开始说话时聚焦的可编辑控件，不进入控制指令解析器。媒体／主机模式继续走指令控制。焦点或光标变化后停止投递，保留转写。

Codex 输入框曾出现 AXSelectedText 写入返回成功、实际没有文字的情况。最终移除直接文字属性赋值，统一使用系统键盘 Unicode 事件；不使用剪贴板。界面区分“已发送”与实际确认，语音页单独保留投递结果。Codex 自身窗口不由电脑工具操作，最终输入效果由用户亲自确认。

Windows 的电脑语音快捷键也按模式分流，原生模式使用系统键盘输入当前文本框，其他模式执行指令；三款遥控器的 Windows 原生语音按键保持系统行为。
